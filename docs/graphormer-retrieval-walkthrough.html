Graphormer KB 迁移后，一次分析到底发生了什么

对应代码：backend/retrieval/retriever.py · backend/retrieval/graphormer.py · backend/llm_judge/judge.py ｜ 数据现状：patterns 表 9,346 行，graphormer_embedding 与 retrieval_fingerprint 100% 填充

0. 先分清「离线侧」和「在线侧」

离线侧（已经做完、躺在库里的东西）——这就是你说的"KB 迁移过来了"：

资产内容在哪
graphormer_pooled.npz (17.8MB)9,346 个 confirmed 候选子图的 784d 入库向量（[768d 池化 | 16 标量]）+ 全库 μ/σ文件 + 已导入 patterns.graphormer_embedding 列
ego_members.npz (12.6MB)上述候选的成员地址并集（12,643 个地址）的 768d ego 向量仅文件（在线时内存里查）
retrieval_fingerprint 列每个候选的 WL 多重集指纹（精排通道分的预计算）patterns 表，9,346 行全填充
structural_features / semantic_embedding 列20d 结构特征向量 + 描述文本 embedding（回退路径用）patterns 表

在线侧（每次 analyze 都要现算的）只有输入子图自己的表示——而它不跑任何神经网络，是"查表 + 加权平均"。

1. 在线全流程（六步）

analyze(地址, hops, time_window) │ ▼ ① graphbuild BFS 展开 → SubgraphResult(节点/边/统计) │ 若历史分页截断/分支失败 → data_quality=degraded ▼ ② 构造查询向量 graphormer_query_vector(canon) ← 不是跑模型！ │ q = [ Σ wᵢ·ego[addrᵢ] / Σ wᵢ (768d) | 16d 标量 ] → L2 │ 其中 ego[addrᵢ] = 从 ego_members.npz 查这个地址的向量 │ wᵢ = 1/(1+depthᵢ)，越靠近种子的地址权重越大 │ ├── 成员覆盖率 ≥ 50% ？──是──→ ③a Graphormer 召回（主路径） │ pgvector: patterns.graphormer_embedding │ cosine 精确扫 Top-500 │ └── 覆盖率 < 50%（live 新地址）→ ③b hybrid 召回（回退） 结构特征 20d 向量 + describe_subgraph 文本 embedding 加权混合召回 ▼ ④ 精排 _rerank final = 0.1·cos + 0.1·wljac + 0.8·ov │ 主路径行带 retrieval_fingerprint → 指纹通道分（免回读 canonical） │ 回退路径行带 canonical_subgraph → 在线现算 channel_scores ▼ ⑤ Top-K 候选 PatternCandidate{分数全部算好： │ wl_kernel_score=0.058… ← 问题就出在下一步丢掉它} ▼ ⑥ LLM judge build_messages 目前只传 description + difference_note （分数不传）→ verdict{matched_pattern, risk_level, confidence}
⚠ 为什么"不跑模型"是对齐要求而不是偷懒：KB 侧 9,346 个向量是离线 batch 用 Graphormer 算好的。若在线侧对输入子图再跑一次模型前向，两侧 embedding 空间反而难保证一致。基准协议（run_round）定义的查询向量就是"ego 成员池化"——把输入子图表示成它地址集合在已知地址向量空间中的加权质心。代价：输入子图的地址必须在 12,643 语料里出现过，否则查不到 ego 向量（coverage 门槛的由来）。

2. 分步细节

① graphbuild（backend/graph_builder/builder.py）

地址种子 → 拥有 UTXO 列表 → BFS 逐层 outspend 展开，产出 canonical 子图。这一步只产出结构（节点 kind=address/transaction、边、层级、金额），还没有任何"向量"。

② 查询向量 = 查表池化（backend/retrieval/graphormer.py:127）

输入：canonical 子图（节点+边）
动作：1. 找出所有 address 节点，逐个去 ego_members.npz 查 768d ego 向量
      2. 按深度加权求和：q_pool = Σ (1/(1+depth_i))·ego_i / Σ (1/(1+depth_i))
      3. 算 16 维标量特征（层级边计数 log10、等额占比、跨链比例…），
         用全库 μ/σ 做 z 归一化
      4. 拼 [q_pool | q_scal] → L2 归一化 → 784d 查询向量
失败条件：地址成员在 ego 语料里的覆盖率 < 50% → 返回 None

覆盖率门槛 = 主路径与回退路径的分界线。12,643 个 ego 地址全部来自 Lazarus confirmed 案例——所以：

场景覆盖率走哪条路
评测集 60 地址（同簇/语料内）高③a Graphormer 主路径
live 真实用户输入的新地址通常 0%③b hybrid 回退

覆盖率不足时静默给零向量会污染排序（全库都会变成"看起来相似"），所以显式回退——这是设计选择，不是缺陷。

③a Graphormer 召回（retriever.py:256）

SELECT … 1 - (graphormer_embedding <=> CAST(:gv AS vector)) AS sim
FROM patterns
WHERE graphormer_embedding IS NOT NULL
ORDER BY graphormer_embedding <=> :gv   ← 精确扫描（显式关 indexscan）
LIMIT 500

9,346 行全表 cosine 在 <50ms 量级；返回的行自带 retrieval_fingerprint。

③b hybrid 召回（retriever.py:276）

dist = :w_struct·(structural_features <=> :sv) + :w_semantic·(semantic_embedding <=> :ev)

注意有 embedding 模型锁（WHERE embedding_model = :model）：查询侧 embedding provider 的模型/维度必须与入库时一致，否则直接报 EmbeddingModelMismatch——防止换模型后新旧向量混比。

④ 精排（retriever.py:335，权重 0.1 / 0.1 / 0 / 0.8）

通道算什么权重
cos阶段 1 召回分（1−dist）0.1
wljacWL 多重集 Jaccard（图结构同构相似度）0.1
fp指纹整体相似0.0
ov出边 multiset overlap（金额主干重合度）0.8 主导

主路径候选：通道分从 retrieval_fingerprint（离线指纹）直接算；回退候选：在线对 canonical 现算。所有分数（含 wl_kernel_score）都装进 PatternCandidate 返回。

⑥ LLM judge 收到的（judge.py:262 build_messages）

pattern_name: mixer_layering_2hop_7nodes
  source: lazarus_confirmed
  provenance: confirmed
  "结构：4 地址 3 交易，恰好 8 条边，根地址 bc1q…"   ← ingest 自动生成模板
  difference vs input: …（仅 Δnode>2 时才有，本例 Δ=0 → 没有）

judge 看不到：wl_kernel_score=0.058（结构弱匹配的正确信号）、final 分、ov 分——全部被丢弃。于是 judge 把 description 里的"恰好 8 条边"读成硬等值条件，#71 的变体案例（7 边）被误杀为 no_match + 0.0。这就是 #71 方案 C（透传分数）要修的最后一公里。

3. 把你原来的表述对到代码上

你的理解实际情况
"graphbuild 得到子图后应该直接 graphormer 做 embedding"方向对，实现是"查表池化"：输入子图不跑模型，用成员地址去 ego 语料查向量做加权平均。跑真模型前向属于未接入的 P2（retriever.py 里 channel_w_align 的注释）
"然后进行粗排召回"对：784d 查询向量 ↔ KB 的 784d 入库向量做 pgvector cosine 粗排 Top-500
"指纹路径"只是精排的实现细节：主路径候选带离线 WL 指纹 → 通道分从指纹算；回退候选没有指纹 → 现算。不影响召回本身

4. 一句话版本

KB 迁移后，一次分析的检索 = 「拿输入子图的地址去 12,643 个已知地址向量里查表 → 按深度加权平均出 784d 查询向量 → 和 9,346 个离线预计算的 KB 向量比 cosine 粗排 → WL/overlap 通道精排 Top-K → 分数目前没有传给 LLM，judge 只读 KB 的描述文本」。live 新地址查不到 ego 向量就回退文本+结构 hybrid 召回。
